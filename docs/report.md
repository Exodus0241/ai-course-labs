## 3. Ход работы
### 3.1. Архитектура RAG системы
Разработанная система построена по классической схеме Retrieval-Augmented Generation. На первом этапе документы производственной тематики загружаются из локальной директории, затем разбиваются на текстовые фрагменты фиксированного размера с перекрытием. После этого для каждого фрагмента вычисляются векторные представления, и они сохраняются в ChromaDB. При поступлении пользовательского запроса система выполняет поиск релевантных фрагментов, формирует контекст и передаёт его в YandexGPT для генерации ответа.

Схема работы:
1. Загрузка документа.
2. Очистка и нормализация метаданных.
3. Чанкинг документа.
4. Построение embeddings.
5. Индексация в ChromaDB.
6. Семантический поиск по запросу.
7. Формирование ответа на основе найденного контекста.

### 3.2. Настроенные компоненты
| Компонент | Реализация | Параметры |
|-----------|-----------|-----------|
| Document Loader | `DocumentLoader` | Форматы: PDF, TXT, MD, DOCX |
| Chunking | `RecursiveCharacterTextSplitter` | Size: 800, Overlap: 120 |
| Embeddings | `paraphrase-multilingual-MiniLM-L12-v2` | Dimension: 384 |
| Vector Store | ChromaDB | Collection: `rag_documents` |
| LLM | YandexGPT | Temperature: 0.3 |

### 3.3. Документы для индексации
Для демонстрации работы системы были подготовлены тематические документы, связанные с предметной областью диплома. В них отражены типовые причины дефектов закупорки, состав данных, которые хранит информационная система, а также сценарии контроля на производственной линии.

Статистика документов:

- Типы: Markdown, TXT
- Тематика: производственный контроль качества, инциденты, линии розлива, укупорочные узлы, уведомления оператора

### 3.5. Адаптация под специальность
RAG-система была адаптирована под тему дипломной работы: «Информационная система контроля дефектов закупорки молочной тары на производстве». Для этого изменён системный промпт, чтобы модель выделяла не только факты из документов, но и предметные сущности производственного процесса.

В специализированной версии системы учтены следующие аспекты:
- причины дефектов закупорки;
- укупорочные механизмы и производственная линия;
- партии продукции и привязка к инцидентам;
- сигналы датчиков и операторские уведомления;
- журналы событий и контроль качества.

Примеры специализированных запросов:
- Какие данные нужно хранить по инциденту закупорки?
- Какие факторы чаще всего приводят к смещению крышки?
- Как связать дефект с партией и линией розлива?
- Какие уведомления должна отправлять система оператору?

Интеграция с дипломом заключается в том, что база знаний RAG может использовать эксплуатационные инструкции, регламенты контроля качества, журналы инцидентов и описания бизнес-процессов для консультирования разработчика, технолога или оператора.
